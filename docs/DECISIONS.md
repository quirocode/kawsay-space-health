# Decisions

One line per decision: date/time · decision · why.

- Sat 10:30 · Concept: Future Self + compound engine + Earth-independent loop · differentiates from status dashboards; backed by NASA resources (see docs/01).
- Sat 10:30 · Client-only, offline-first, deterministic rules engine · demo cannot depend on a network or a model.
- Sat 11:00 · Direction "Landing day in 4 tasks" (stand, see, move, think) on top of Future Self · turns the readiness number into something a judge understands in 10 s; backed by gravity, cardio, fitness and SANS pages. Discarded "countermeasure debt" (guilt tone, invented model) and a standalone delay animation (kept as one line in the brief).
- Sat 11:15 · Contract v1: thresholds carry sources; projections carry a daily series; `LandingTask[]` replaces canStand…canThink; `project()` takes an optional `CountermeasurePlan`; Engine gains `indicators()`, `verify()`, `brief()`; `evaluate()` takes `nowTs` · the engine stays pure (no clock) and the UI can show the plan's effect and the closed loop.
- Sat 11:15 · CO₂ yellow line = 3 mmHg (1-hour average) from NASA-STD-3001 Technical Brief OCHMO-TB-004 · the only official vital-sign-style threshold that backs our headache rule.
- Sat 11:30 · Stack: React 19 + Vite 8 + TypeScript + Tailwind v4 + Vitest; no shadcn/ui · custom tablet design; shadcn setup costs more than it saves.
- Sat 11:30 · Zustand with localStorage persistence instead of Dexie · tiny dataset (one crew member, ~3k readings); fewer moving parts.
- Sat 11:30 · Hand-drawn SVG for the body and trajectory instead of Recharts · one curve and one figure; full control of the look.
- Sat 11:30 · Hash routing (wouter) + vite-plugin-pwa · works offline and on any static host without rewrites.
- Sat 11:30 · Self-hosted fonts (Atkinson Hyperlegible, IBM Plex Mono via @fontsource) · offline; Atkinson is designed for legibility.
- Sat 11:30 · Provisional engine in `src/app/engine/stubEngine.ts` implements the full Engine with simplified logic · UI work starts before P3 delivers; P1 swaps pieces in `src/app/engine/index.ts`.
- Sat 11:30 · "Watch" amber darkened to #9A6A00 in day mode · WCAG AA contrast for text on the light background.
- Sat 11:50 · Vercel project `kawsay` (team quirocode) linked to GitHub; public production URL https://kawsay-ten.vercel.app; previews per PR stay behind Vercel login · judges need a public link; previews only for the team.
- Sat 12:10 · Sol 142 calibrated to readiness 66 → 89 (was scripted as 68 → 84); "Climb out and walk" stays Watch with the plan · bone cannot recover in 38 days; forcing it to OK would contradict NASA's 1–1.5 %/month. The honest message ("start earlier") is stronger for Validity.
- Sat 12:10 · Readiness points are piecewise (30 at the red line, 80 at the green line, 100 at pre-flight) · an "OK" task near the line should not score the same as a perfect one.
- Sat 12:10 · Future Self opens on arrival day; the time slider previews "if you landed on Sol N" by calling `project()` with `arrivalDay = N` · no contract change needed.
- Sat 12:10 · Woven timeline: one thread per day, height = exercise vs 90 min target; days under 75 % show in amber · the 6 short days are visible at a glance, which is the demo's first beat.
- Sat 12:40 · P3's first upload (src/data/indicators.ts, src/data/data/indicators.test.ts) did not match P3-01 (wrong path, different ids, no thresholds, empty URLs) and broke CI on main. P1 rebuilt `src/domain/indicators.ts` to the brief, keeping P3's measurement copy, and removed the misplaced files · the engine, rules and demo data all depend on the P3-01 ids. Dropped from the draft for now: radiation dose (600 mSv career limit is NASA-STD-3001 but no projection uses it yet), urine colour, appetite, Amsler test — candidates for "extra" scope.
- Sat 12:40 · Provisional engine now reads indicators and sources from `src/domain/indicators.ts` · one source registry for the whole app.
- Sat 13:00 · Design system from P4's pen.dev file adopted: light theme + 5 night palettes (Mars, JWST, Lunar, Aurora, Earthrise), "Inti" terracotta as brand, Instrument Sans + JetBrains Mono. Tokens exported to `design/exports/tokens.json` and generated into `src/app/tokens.css` by `scripts/tokens-to-css.mjs` · single source of truth, mapped once.
- Sat 13:00 · The arrival-day ("future") body uses Inti; the old violet "Dusk" is dropped · the design reserves violet-grey for stale data, and two violets would confuse "projected" with "old data".
- Sat 13:00 · The .pen file contains only variables (no screens or body artwork yet); layout stays as built until P4 adds screens · nothing to implement beyond the design system.
- Sat 13:00 · Design fonts referenced first with Atkinson/IBM Plex as offline fallback · npm registry unreachable (ECONNRESET) at the time; bundle @fontsource/instrument-sans and @fontsource/jetbrains-mono when the network is back.
- Sat 13:15 · Screens designed in pen.dev on top of P4's variables; the body figure in the design uses the same geometry as the app (`design/exports/body.svg`) · design and code stay in sync, and the figure keeps one id per zone.
- Sun 12:10 · Public landing page at `/`, the app moves to `/app/` (two Vite pages); old `/#/…` links redirect to `/app/#/…` · judges land on a page that explains KAWSAY in seconds, with buttons to the demo, the video and the Windows download. Layout inspired by quenaris.vercel.app (design only, our own copy in `content/landing.json`).
- Sun 12:10 · The desktop .exe opens `/app/` directly, never the landing page · the crew tool should start in the tool.
- Sun 12:10 · NASA blue #0B3D91 (Pantone 286 C) is the action colour; the five night palettes become one (from Earthrise) · team decision. #0B3D91 on the dark background reads at under 2:1, so text, outlines and the arrival-day self use a lighter tint (`--brand-ink`, #8DB4FF at night); filled buttons keep #0B3D91 with white text. Night is now the default theme.
- Sun 12:10 · Choosing an environment applies it at once and the header shows it as a chip next to the title · there was a separate "Use this environment" button, so the header looked stale after a choice.
- Sun 12:10 · Daily check values are text fields (numeric keyboard on touch, autofocus with a mouse) as well as the keypad; Enter moves on, number keys answer the 1–5 scales · desktop users could only click the pad.
- Sun 12:10 · "Download for Windows" points at the GitHub release `latest` · the packaged app folder is ~360 MB, too big for the Vercel deploy; the release still has to be published.
- Sun 12:45 · Save public landing preferences locally, default to English and night, and pass the language through the existing demo query parameter · keeps both entry points consistent without changing the demo's theme preference.
- Sun 13:00 · "Sol" becomes "Day" ("Día") everywhere: the header reads "Day 142 of 180 · 38 days to landing" with an (i) that explains mission days, landing day and what a sol is; "Arrival" becomes "Landing" and Future Self says "in 38 days" · "Sol" was never explained, and a sol is a Mars day, while in transit the crew counts ordinary days. Internal names (`sol142.ts`, test titles) stay.
- Sun 13:30 · Mission name, crew member, today's mission day and landing day are editable on the Environment screen, now labelled "Mission"; the header shows "Inti-1 · A. Quispe" · the crew should see whose mission this is, and the days must match the real mission. Day 1 is launch day; landing can't be before today; up to 1,000 days. "Inti-1" is a fictional demo name. The seeded readings stay on day 142, so changing today's day is a what-if for the projection; "Demo → Morning" restores the seed.
- Sun 13:45 · Band connection: a "Connect" screen before "Watch" (start → get ready → system device list → live), modelled on how phone fitness apps add a device · the browser's device list cannot carry instructions, so a checklist comes first. Research: `reports/Conexión Xiaomi Mi Band 7.md` (local, not in the repo).
- Sun 13:45 · Web Bluetooth with the standard Heart Rate Service (0x180D / 0x2A37) for both the deployed app (Chrome, Edge) and the .exe (Electron answers `select-bluetooth-device` with a native dialog in `desktop/main.cjs`) · one code path, no internet, no native plugin. Tauri was ruled out: WebView2 has no Web Bluetooth.
- Sun 13:45 · The Xiaomi Smart Band 7 is not guaranteed to share heart rate on 0x2A37 without Xiaomi's pairing key (Gadgetbridge: third-party live heart rate "not working"). We do not implement the proprietary Zepp OS handshake (AGPL code, key needs Xiaomi servers once); any standard chest strap works through the same screen, and the Sol 142 demo stays the default · the demo must not depend on one band's firmware.
- Sun 13:45 · Live band heart rate replaces the Watch's heart-rate tile only; the watch alarm rules still run on the demo series and the tile shows a "Live" chip, not a health badge · the rules need activity context the band does not send. Link limits (old after 5 s, lost after 30 s, 5 reconnect attempts) are prototype values in `src/app/band/heartRate.ts`.
- Sun 13:00 · Keep “Try the demo” in English with a fixed width in the landing header. Use one language button and a day/night switch in the app header, updating the language in existing demo links when the user switches.
- Sun 14:01 · Add a bilingual four-screen tour to the public landing page, using screenshots of the simulated demo and links to each live screen · visitors can explore and try the workflow without setting up a device.
- Sun 14:25 · Replace the shared 2D body figure with two locally served 3D anatomical layers, selected from Z-Anatomy/BodyParts3D via atlas-proto. Meshes retain names and map to existing body zones, so selecting an individual structure opens the existing zone assessment. The zone list remains available for regions absent from the mesh selection and when WebGL is unavailable. Model derivatives and attribution are distributed under CC BY-SA 4.0 in public/anatomy.
- Sun 14:43 · Keep both anatomy layers in the same full-body frame. A translucent skin mesh provides spatial context, and six muscle groups retain the existing muscular zone assessment.
- Sun 15:17 · Organize the demo navigation by health and operations. The future-self page separates the readiness score, 3D comparison, and assessment, with a full-width date slider and a shared muscle and organ toggle.
